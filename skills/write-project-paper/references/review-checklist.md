# 四轮复审清单

## 第一轮：事实与引用

- 标出所有定量结果、完成状态、版本和因果陈述，逐项回到原始证据。
- 检查单臂/双臂、仿真/真机、训练/评测、开发集/测试集等边界是否被混淆。
- 查出“模型负责安全检查”“输入约束等同于硬约束”等职责误写。
- 验证每个外部链接、作者、标题、年份和正文用途。
- 把推断写成推断，把缺失结果写成缺失。

## 第二轮：初学者阅读连续性

- 读者遇到缩写前是否已经看到全称和用途？
- 正文是否把配置名、代码变量或团队内部简写当作自然语言？若能直接写出实际行为，就改写原句，不增加术语表。
- 每个保留的正式术语是否确实会在后文复用，或能帮助读者查阅资料？首次出现时是否先说明它解决的具体问题？
- “增益、死区、滤波、锁存、容差、p95、峰峰值”等词若出现，读者能否在同一句读到具体计算或可观察结果？
- 新模块出现时是否说明输入、输出及其在整条链路中的位置？
- 每个“它”“该方法”“上述结果”能否唯一定位指代对象？
- 相关工作是否解释方法机制，而不只列名称？
- 公式前是否定义符号，公式后是否解释结果如何用于项目？
- 教程是否说明在哪台机器、哪个目录和哪个环境运行？

可让不了解项目的人只阅读到当前段落，然后回答“系统现在拿到什么、做什么、得到什么”。答不出时应重写当前段落。添加术语表或要求读者跳到后文查询，不算解决连续性问题。

## 第三轮：方法与复现

- 数据来源、成功筛选、训练/验证/测试划分是否清楚？
- 输入输出维度、单位、坐标系和归一化是否明确？
- 冻结模块、训练模块、损失和关键超参数是否明确？
- 上游软件原有能力与本项目自定义代码是否分开？
- 评测是否包含模型加载、环境执行、成功条件和失败分类？
- 命令、配置路径和提交号是否真实可用？
- 教程每一步是否有预期输出、验收条件和停止条件？

## 第四轮：中文与版式

- 按段落辨认背景、前人工作、研究设计、观察和解释。项目自己的选择、判断和局限是否有明确责任者？前人结论是否正确归属作者？不能以“我们”出现次数代替此项检查。
- 搜索“不是”“而是”“并非”“值得注意的是”“这意味着”，逐句判断是否必要。
- 搜索“不是手改”“没有造假”“不是挑选最好”“没有偷偷改”“没有补造”等防御性自证；把有方法学价值的部分改成选择规则、证据来源或适用范围，纯粹辩解直接删除。
- 合并连续的一句一段，拆开塞入过多概念的长句。
- 删除重复结论、空泛评价和没有信息增量的过渡句。
- 保留明确主语，减少名词堆叠和英文直译语序。
- 图题、表题、正文引用及编号一致。
- HTML 检查标题层级、表格溢出、代码块可读性和链接；只有用户要求分页格式时才检查标题孤悬、表格行和图题拆页。
- 仅在用户明确要求 PDF 时：检查空白页、可点击链接、标题元数据和中文字体；否则此项不适用，不生成 PDF。

完成检查后列出仍然存在的限制。阶段报告不应因版式完整而被表述成最终研究结论。
